## 1. 背景

当前有两套割裂的工具：

1. **invest-folio**：单文件 `portfolio.html`（原生 HTML/CSS/JS，约 1500 行），浏览器打开即用。它维护当前持仓数量，实时抓取公开行情接口，计算 CNY 市值、7 大类配置占比、再平衡缺口、券商/币种分布。它没有后端、没有数据库、没有交易流水、没有成本与盈亏。
2. **随手记（www.sui.com）**：用于记录投资相关的资金流水，导出为 4 个归一化 CSV（收入/支出/转账/余额变更，共 444 条，时间范围 2026-01 ~ 2026-11）。流水只有金额，没有份额、单价、成本、交易 ID；每月末还有一批手工录入的「红利收益/成长收益/…」估值补丁。

两者的痛点：

- 记账工具不能动态跟踪资产单价，只能手工补月度估值；
- 估值工具没有交易流水，无法回答「投资到底赚没赚」；
- 同一只基金在不同机构无法合并统计；
- 两套工具意味着日常生活里要多用一个工具。

## 2. 目标

构建一个**单机 Android App**，替代 invest-folio 和随手记（仅投资记账部分），在一个工具里完成：

- 投资事件（转账/买卖、分红、利息、出入金、费用等）的录入与流水管理；
- 基于实时行情的持仓估值、7 大类配置与再平衡提示；
- 类别级盈亏、总资产曲线、累计投入/取出、费用统计等分析；
- 数据本地保存、可通过手机文件管理器手工备份。

## 3. 非目标（v1 不做）

- 日常消费/收入记账；
- 负债账户（房贷、信用卡等）；
- 多用户、多设备同步、云服务、账号体系；
- iOS、Web、桌面端；
- 应用商店上架与正式签名发布；
- 加密货币、期货、期权、融资融券；
- 逐笔成本法、逐笔收益、XIRR/TWR 等高级收益指标；
- 从随手记 CSV 自动批量导入（后续单独讨论，v1 先手工录入 + 模拟数据开发）；
- 后台定时刷新、推送通知；
- 数据加密（用户要求纯文本可读）；
- 深色模式、多语言（可作为后续增强）。

## 4. 用户与运行环境

- 单一用户（项目所有者本人）。
- 目标手机：Xiaomi 17 Ultra（日常使用）；Redmi 14C（开发/调试机）。
- App 必须**独立在手机上运行**，不依赖局域网内的任何其他机器或服务器。
- 数据固定保存在手机 `Documents/folio-prism/`；备份通过手机系统文件管理器手工操作。
- 需要联网获取行情；无网络时按第 6.1 节处理。
- UI 语言：中文。
- App 显示名：**投资组合**；包名：`com.jimbozhang.folioprism`。

## 5. 已确认的产品决策（Decision Log）

| ID | 决策 |
|---|---|
| D-01 | 原生 Android App（Kotlin + Jetpack Compose），替代 invest-folio 与随手记的投资记账部分；不记录日常收支，不做负债。 |
| D-02 | 单机运行，数据固定在手机 `Documents/folio-prism/`；不做应用内导入/导出 UI；备份由用户在文件管理器中手工完成；README 写明数据路径。 |
| D-03 | 目标机 Xiaomi 17 Ultra，开发机 Redmi 14C；只编译 debug APK 自用。 |
| D-04 | 首页 = 总资产 + 7 大类卡片（含再平衡信息），不显示盈亏；盈亏、曲线、分布、累计投入/取出、费用统计等放在独立图表页。 |
| D-05 | 7 大类固定：红利、成长、美股、美债、中债、黄金、现金。类别是用户给标的分配的「角色」，不是资产类型；例如债券基金 000015 可被归为现金。现金类标的同样需要实时估值。 |
| D-06 | 账户与标的分离：账户 = 机构（银行/券商），标的独立维护；持仓 = 机构 × 标的；同一标的在多个机构共享同一条标的记录。 |
| D-07 | 现金标的化：现金是「现金」类别下的标的（CNY/USD/HKD/CNH/活钱宝/美元定期等）；数量即金额；也可包含有净值的现金类基金（如 000015）。 |
| D-08 | 事件统一：买入、卖出、基金转换、跨机构搬仓、换汇都归为「转账」；另设收益（分红/利息）、外部入金/出金、支出、期初、调整事件。 |
| D-09 | 分红全部为现金分红，不做红利再投资。若用户实际做了再投资，由用户手工录入一笔买入转账，不并入分红事件。分红事件记录：来源标的/机构、入账现金账户、金额、是否立即转出到外部消费账户。 |
| D-10 | 多币种：交易按原币存储；单项资产按原币显示；只有需要把多个币种金额加总时（总资产、类别汇总、占比等）才折算为 CNY。录入时自动取当日汇率且允许手改；历史估值使用历史汇率。 |
| D-11 | 当前行情只使用 `portfolio.html` 中每个标的类型对应的**首选数据源**，不使用备选数据源；首选源失败即视为行情获取失败。打开时刷新一次 + 下拉刷新；无后台/定时刷新。 |
| D-12 | 启动价格门禁：任一持仓的必需价格（含汇率）无法获取时，不进入主界面，进入调试页。价格缓存**不能**作为当前估值的备用数据源。 |
| D-13 | 调试页：打印失败项、首选数据源、错误原因与日志；允许刷新；允许把日志保存到存储；允许为失败标的临时设置手工价格并重试。 |
| D-14 | 历史数据：按需抓取历史价格/净值/汇率并缓存；缓存用于历史统计，可随数据一起被用户备份；用户指定的历史区间必须可计算。 |
| D-15 | v1 图表：类别盈亏、总资产变化曲线、累计投入/取出、费用统计、机构分布、币种分布。盈亏口径为「市值变化扣除资金流」；v1 不做逐笔成本/收益率。「收益构成」即类别盈亏，不另设图表。 |
| D-16 | 数据存储：单个 JSON 文件（带 schemaVersion），原子写入 + 带时间戳备份（默认保留 5 份）；历史价格缓存独立文件；纯文本、不加密。 |
| D-17 | 机构、标的、7 类目标区间、黄金加价等在 App 内编辑；同时允许用户在 App 关闭时直接手工编辑 JSON 文件来设置和记录流水。 |
| D-18 | 历史回填：用户计划录入手头 4 个 CSV 中的全部真实流水（每月手工估值行除外）；录入效率与导入方式在实现前另行讨论。开发阶段用调试 JSON 文件，不提供模拟数据开关。 |
| D-19 | 计算行为与 `portfolio.html` 相同（除本文件明确修改的显示/事件规则外）。保留红利/组合双口径、再平衡缺口公式、黄金阈值价、黄金机构加价、机构/币种分布。 |
| D-20 | 技术实现细节（精确盈亏公式、缓存文件结构、图表库等）由开发方决定，但必须满足本文档的可观察行为。 |
| D-21 | 不提供数据目录选择，也不专门制作启动设置页；直接使用 `Documents/folio-prism/`。若系统未授予「所有文件访问」权限，跳转系统授权页。 |
| D-22 | 每笔事件在保存时把相关价格、汇率与折算后的 CNY 金额写入 JSON；即使历史价格数据源缺失或缓存损坏，也能基于事件快照计算交易行为之间的盈亏（近似结果需标记）。 |
| D-23 | 转账记录「转出数量」与「转入数量」两个量，各自使用转出/转入标的的原币单位（现金为金额，有净值标的为份额）。两者按价值默认相等，也允许不同；差额自动记一笔「损耗支出」（可为负值）。 |
| D-24 | 设独立的「支出」事件：投资手续费、转账损耗等；支出金额可以为负值（表示返还/收益）。 |
| D-25 | 不阻止也不提示会导致负持仓/负现金的编辑或删除；数据的正确性由用户自行负责。 |
| D-26 | v1 将 CNH 视作 CNY（1:1），后续迭代再支持 CNH/CNY 汇率。 |
| D-27 | 每笔事件保存价格/汇率快照（D-22）；历史价格缓存只用于更精确的逐日曲线与区间估值，不是当前价格来源。 |
| D-28 | 预期事件规模为 1 万条（当前 444 条只是起点），性能设计按此规模考虑。 |
| D-29 | 日志允许包含标的代码与名称，不记录金额、数量、汇率。 |
| D-30 | 美股/美债等类别中，人民币计价资产（如 513500）以人民币显示，不显示美元等值；美元计价资产（如 VOO）直接显示美元价值，并显示人民币等值。类别汇总仍以 CNY 为口径，另给出美元计价资产的小计。 |

## 6. 功能需求

编号规则：`FR-<模块>-<序号>`。每条需求都应能转化为验收测试。

### 6.1 启动与价格门禁

- **FR-START-01**：App 启动后先加载本地数据文件；若文件不存在，直接在固定目录创建空数据文件并显示空状态首页，不进入应用内设置页。
- **FR-START-01A**：固定数据目录为 `Documents/folio-prism/`。若系统未授予「所有文件访问」权限，跳转系统授权页；授权后继续；用户拒绝则显示调试页说明原因。
- **FR-START-02**：加载数据后，必须获取所有「必需价格」后才能进入主界面。必需价格包括：
  - 所有数量非零、`kind=quoted` 的标的的当前价格；
  - 所有非 CNY 现金/持仓所需的当前汇率（v1 为 USD/CNY、HKD/CNY；CNH 视作 CNY，不需要汇率）；
  - 黄金类持仓所需的金价；
  - 已配置手工价格的标的视为价格可得，不触发失败。
- **FR-START-03**：任一必需价格获取失败（网络错误、接口无数据、解析失败、超时等），**不得进入主界面**，显示调试页。
- **FR-START-04**：调试页必须显示：每个失败项的机构、标的代码/名称、所需价格类型、首选数据源、错误原因、时间；以及最近的应用日志。提供「刷新」「保存日志」「设置手工价格并重试」按钮。
- **FR-START-05**：保存日志时写入数据目录下的 `logs/`，文件名带时间戳；日志可包含标的代码与名称，不得包含金额、数量、汇率。
- **FR-START-06**：刷新成功后进入主界面；刷新仍失败则留在调试页。
- **FR-START-07**：价格缓存只用于历史统计，不参与启动估值，不得作为「当前价格」的备用源。
- **FR-START-08**：数据文件损坏/无法解析时，进入调试页并显示错误；不得静默重置数据。
- **FR-START-09**：当前价格获取成功后，顺手把当日价格写入历史价格缓存（best effort）；缓存写入失败只记录警告，不阻塞进入主界面。

### 6.2 首页

- **FR-HOME-01**：显示总资产（CNY，汇总口径）。
- **FR-HOME-02**：显示红利小计与占比、组合（非红利）小计与占比。占比规则见 6.9。
- **FR-HOME-03**：显示 7 大类卡片，顺序按设置中的类别顺序。每张卡片显示：
  - 类别名称、当前市值（CNY 汇总）；
  - 当前占比、目标占比；
  - 目标金额、最小/最大区间金额；
  - 是否在目标区间内（颜色标识）；
  - 再平衡缺口（高于/低于目标/下限/上限的金额）；
  - 黄金类别额外显示「下限单价」「上限单价」（按当前金价源单位：USD/盎司或 CNY/克）。
- **FR-HOME-04**：单项资产按原币显示：
  - 人民币计价资产（如 513500）显示人民币，不显示美元等值；
  - 美元计价资产（如 VOO）显示美元价值，并显示人民币等值；
  - 类别汇总仍以 CNY 为口径；若类别内存在美元计价资产，额外显示「美元资产小计（原币）」及其人民币等值，而不是把整个类别折算成美元。
- **FR-HOME-05**：点击类别卡片可展开该类的持仓表：机构、标的代码/名称、数量/份额、单价（原币）、市值（原币）、占比；美元计价的持仓额外显示人民币等值；再次点击折叠。
- **FR-HOME-06**：首页不显示盈亏金额。
- **FR-HOME-07**：首页支持下拉刷新；刷新失败按 FR-HOME-08 处理。
- **FR-HOME-08**：刷新失败时进入全屏调试页，直到刷新成功；不得用旧价格或缓存价格展示总资产。
- **FR-HOME-09**：首页不得出现 `portfolio.html` 中的调试面板。

### 6.3 交易与事件

- **FR-TX-01**：支持以下事件类型：
  1. **转账**：任意两个持仓（机构 × 标的）之间移动价值。买入、卖出、基金转换、跨机构搬仓、现金换汇在账本上都统一为转账；UI 可提供「买入/卖出」等快捷预设，但生成的仍是转账事件；
  2. **收益**：现金分红/利息，入账到现金标的；支持立即转出到外部消费账户；
  3. **外部入金**：外部 → 现金标的，属于本金投入；
  4. **外部出金**：现金标的 → 外部，属于本金取出/消费；
  5. **支出**：投资手续费、转账损耗等；金额可以为负值（返还/收益）；
  6. **期初**：期初现金余额 / 期初持仓数量；
  7. **调整**：对某持仓做数量或金额调整（平账），需填写原因。
- **FR-TX-02**：转账必须记录两个量：
  - **转出数量**（`fromQuantity`）：转出标的的原币单位数量；现金标的为金额，有净值标的为份额；
  - **转入数量**（`toQuantity`）：转入标的的原币单位数量；规则同上；
  - 两者按价值默认相等，也允许不同；涉及有净值标的时需记录相应单价；跨币种时记录汇率；
  - 当转出与转入价值不相等时，自动生成一笔关联的「损耗支出」，金额 = 转出价值 − 转入价值（可为负值）。
- **FR-TX-03**：投资手续费使用独立的「支出」事件记录，不附着在转账事件上。
- **FR-TX-04**：收益事件字段：来源标的/机构（利息可为空）、入账现金账户、金额、币种、是否立即转出到外部（转出后自动生成一笔关联的外部出金）。**分红全部为现金分红**，不支持在分红事件里做再投资；再投资由用户手工录入一笔买入转账。
- **FR-TX-05**：所有金额、数量、单价使用十进制精确表示，禁止二进制浮点直接累加。
- **FR-TX-06**：事件列表按时间倒序展示，支持按时间范围、机构、标的、类别、事件类型筛选。
- **FR-TX-07**：事件可编辑、可删除；**不阻止也不提示**会导致负持仓/负现金的编辑或删除；数据的正确性由用户自行负责。
- **FR-TX-08**：交易录入时自动带出当日汇率（如需要），允许手动修改；修改后保存到事件中。
- **FR-TX-09**：持仓数量、现金余额由事件推导；UI 不提供直接改持仓的入口（用户仍可在 App 关闭时手工编辑 JSON）。
- **FR-TX-10**：录入表单应支持「数量、单价、金额三者输入其二自动算第三」，减少手工计算。
- **FR-TX-11**：事件保存后立即参与估值与图表计算。
- **FR-TX-12**：删除机构或标的时，若存在引用它的事件，必须阻止；应先处理相关事件（结构性引用保护，与 D-25 的数值正确性无关）。
- **FR-TX-13**：每笔事件保存时，把相关价格、汇率、折算后的 CNY 金额写入 JSON（能取到就写），供历史数据缺失时的盈亏回退计算使用。
- **FR-TX-14**：手工修改 JSON 必须在 App 关闭时进行；App 运行期间的修改可能被覆盖。

### 6.4 图表页

- **FR-CHART-01**：总资产变化曲线：
  - CNY 口径；
  - 按日数据点；
  - 时间范围可选：近 1 月、近 3 月、今年至今、近 1 年、全部、自定义；
  - 缺失历史数据的日期必须显示为缺口，不得用 0 或伪造值填充；
  - 点击/长按可查看某日总资产。
- **FR-CHART-02**：类别盈亏：
  - 用户可选时间范围；
  - 展示 7 大类（或仅非零类别）的盈亏金额（CNY）；
  - 以表格 + 柱状图呈现；
  - 计算口径见 6.9；历史数据不足的类别标记为「数据不完整」或「近似」。
- **FR-CHART-03**：累计投入/取出：
  - 用户可选时间范围；
  - 展示外部本金投入、外部本金取出（含消费）的累计值，以及净投入；
  - 数据来自外部入金/出金事件，不依赖历史行情，因此始终可计算；
  - 以折线或柱状图呈现。
- **FR-CHART-04**：费用统计：
  - 用户可选时间范围；
  - 汇总「支出」事件金额（含投资手续费、转账损耗；负值返还/收益参与抵扣）；
  - 可按月份/类别/支出类型分组展示；
  - 以表格 + 柱状图呈现。
- **FR-CHART-05**：机构分布：按机构汇总当前 CNY 市值，显示金额与占比；支持机构显示别名（如「人民银行」显示为「熊猫金币」，可配置）。
- **FR-CHART-06**：币种分布：按当前 CNY 市值展示 CNY/USD/HKD/实物黄金等；CNH 在 v1 视作 CNY；分类规则见 6.9。
- **FR-CHART-07**：「收益构成」即类别盈亏（FR-CHART-02），不另设图表。
- **FR-CHART-08**：历史行情获取中显示加载状态；失败时显示错误与该区间的缺口，允许重试。
- **FR-CHART-09**：历史价格缓存可被用户通过文件管理器备份；App 内显示缓存文件路径与最近更新时间。

### 6.5 设置

- **FR-SET-01**：机构管理：新增/编辑/删除机构；字段至少包含名称、类型（银行/券商/其他）、图表显示别名、备注。
- **FR-SET-02**：标的管理：新增/编辑/删除标的；字段至少包含：
  - 类别（7 选 1）；
  - 代码、名称；
  - 币种；
  - 单位（份/股/克/元/张等）；
  - 标的类型：`现金`（数量即金额）或 `有净值`（数量 × 单价）；
  - 行情方式：自动 / 手工价格；
  - 手工价格（如选择手工）；
  - 价格与数量的小数精度。
- **FR-SET-03**：类别与再平衡规则：编辑 7 类的目标比例、最低、最高；类别顺序可调整；类别名称与颜色可调整（但不允许删除/新增类别）。
- **FR-SET-04**：黄金：按机构配置人民币/克加价；选择默认金价源（XAU 或 AU9999）。
- **FR-SET-05**：数据与备份：显示固定数据目录 `Documents/folio-prism/`、数据文件路径、价格缓存路径、最近备份时间；可查看备份列表；备份通过文件管理器完成，App 不做导入/导出 UI。
- **FR-SET-06**：行情与日志：显示当前行情源配置、最近一次刷新时间、日志入口；可进入调试页查看最近日志。
- **FR-SET-07**：关于：App 版本、构建时间、开源许可。
- **FR-SET-08**：所有设置修改立即生效并原子写入数据文件。
- **FR-SET-09**：设置页提示：允许在 App 关闭时手工编辑 JSON；App 运行期间修改可能被覆盖。

### 6.6 数据存储与备份

- **FR-DATA-01**：主数据保存为单个 JSON 文件，包含 `schemaVersion`、设置、机构、标的、事件。
- **FR-DATA-02**：写入必须采用「临时文件 + 校验 + 原子替换/恢复」策略，避免断电或崩溃导致文件损坏。
- **FR-DATA-03**：每次写入前保留带时间戳的备份，默认保留最近 5 份（可在设置中调整）。
- **FR-DATA-04**：历史价格缓存保存为独立 JSON 文件，与主数据同目录，可被文件管理器备份。
- **FR-DATA-05**：数据文件与缓存文件固定放在 `Documents/folio-prism/`，不提供目录选择；README 写明路径。若系统未授予「所有文件访问」权限，跳转系统授权页。
- **FR-DATA-06**：App 不提供导入/导出 UI；用户通过文件管理器复制文件完成备份，或在 App 关闭时手工编辑 JSON。
- **FR-DATA-07**：JSON 使用 UTF-8、缩进可读；金额/数量/单价以十进制字符串存储。
- **FR-DATA-08**：schemaVersion 升级时，App 必须能迁移旧文件；迁移前自动备份。
- **FR-DATA-09**：主数据文件缺失但备份存在时，调试页应提示可从备份恢复（不自动覆盖）。
- **FR-DATA-10**：手工编辑的 JSON 在启动时校验；格式或 schema 不合法时进入调试页并指出错误位置，不静默修复。

### 6.7 行情与刷新

- **FR-QUOTE-01**：当前行情只使用 `portfolio.html` 中每个标的类型对应的**首选数据源**；不使用备选数据源；首选源失败即视为行情获取失败。
- **FR-QUOTE-02**：标的行情路由至少支持：
  - 场外基金（6 位代码，净值）；
  - 场内 ETF/债券（6 位代码，现价）；
  - 美股/美股 ETF（字母代码，USD）；
  - 黄金（AU9999 或 XAU）；
  - 现金（CNY 不需要行情；USD/HKD 需要汇率；CNH 视作 CNY）；
  - 手工价格。
- **FR-QUOTE-03**：刷新策略：打开时刷新一次 + 用户下拉刷新；不做后台/定时刷新。
- **FR-QUOTE-04**：同一标的被多个机构持有时只取一次价格。
- **FR-QUOTE-05**：数量为 0 的标的不要求行情。
- **FR-QUOTE-06**：行情失败时记录首选数据源、请求参数概要、错误原因与时间，供调试页展示。
- **FR-QUOTE-07**：所有必需价格获取成功后才能展示总资产；不得用旧价格、缓存价格或 0 代替。

### 6.8 历史行情与缓存

- **FR-HIST-01**：历史价格用于：总资产曲线、类别盈亏、历史持仓估值。
- **FR-HIST-02**：首次查询某区间时，App 按需抓取缺失的历史数据并写入缓存；后续查询优先读缓存。
- **FR-HIST-03**：历史数据源在实现阶段必须在目标手机上验证；实现前需给出每个标的类型的一个首选数据源清单（不使用备选源；失败即按 FR-HIST-04 处理）。已在 Redmi 14C 上验证：基金用东财 pingzhongdata、场内 ETF/债券用腾讯 kline、美股用新浪财经日线、汇率用 Frankfurter；黄金历史暂用新浪上海金期货 AU0 连续合约作为 AU9999 的近似，并在日志/界面注明。
- **FR-HIST-04**：数据源失效或历史数据缺失时：
  - 不得伪造数据；
  - 曲线显示缺口；
  - 盈亏标记「数据不完整」；
  - 提供重试；
  - 允许用户手工补录某日价格，补录值写入缓存（source=manual），并优先于自动数据。
- **FR-HIST-05**：缓存文件与主数据文件一起可被用户备份。
- **FR-HIST-06**：当前价格刷新成功后，把当日价格写入历史缓存，作为未来历史数据的一部分。
- **FR-HIST-07**：非交易日（周末/节假日）沿用最近一个交易日的收盘价；缺失交易日不得用相邻价格冒充，必须标记缺口。
- **FR-HIST-08**：即使历史数据源缺失或缓存损坏，也要能基于事件中保存的价格/汇率快照（FR-TX-13）计算交易行为之间的盈亏；此类结果标记为「近似」，并说明依据。

### 6.9 计算规则（产品可观察行为）

计算行为以 `portfolio.html` 为准（除本文件明确修改的显示/事件规则外）。以下为实现摘要，开发者负责逐条对齐。

- **FR-CALC-01 估值**：
  - `kind=cash`：`市值CNY = 数量 × 汇率(币种→CNY)`；CNY 汇率为 1；CNH 在 v1 视作 CNY。
  - `kind=quoted`：`市值CNY = 数量 × 单价 × 汇率(标的币种→CNY)`。
  - 黄金：`单价CNY/克 = 金价(CNY/克) + 机构加价`；若金价源为 XAU，则 `金价CNY/克 = XAU美元/盎司 ÷ 31.1035 × USD/CNY`。
  - 总资产 = 所有持仓市值CNY之和。
  - 单项资产展示使用原币；CNY 仅用于需要加总的汇总口径。
- **FR-CALC-02 双口径**：
  - `totalValue` = 全部资产之和；
  - `portfolioValue` = `totalValue` − 红利类市值；
  - 红利占比 = 红利市值 / `totalValue`；
  - 非红利类别占比 = 类别市值 / `portfolioValue`；
  - 红利的目标/上下限金额用 `totalValue` 作为基数计算；
  - 非红利类别的目标/上下限金额用 `portfolioValue` 作为基数计算；
  - 分配总览图的视觉宽度以 `totalValue` 为统一分母（保留 invest-folio 行为）。
- **FR-CALC-03 再平衡金额**：
  - `dynAmount(p, base, catValue) = p × (base − catValue) / (1 − p)`；
  - 目标/下限/上限金额分别代入对应比例；
  - 缺口 = 当前市值 − 目标金额（或下限/上限金额）；
  - 缺口展示逻辑保留 invest-folio：低于目标时显示下限缺口，高于目标时显示上限缺口。
- **FR-CALC-04 黄金阈值价**：
  - `黄金总克数 = Σ 黄金类标的数量`；
  - `其他资产 = portfolioValue − 黄金类市值`；
  - `阈值单价CNY/克 = p × 其他资产 / ((1 − p) × 黄金总克数)`，p 为下限/上限比例；
  - 若当前金价源为 XAU，显示为 `USD/盎司 = 阈值单价CNY/克 × 31.1035 ÷ USD/CNY`；否则显示 `CNY/克`。
- **FR-CALC-05 盈亏（v1）**：
  - 只计算类别级/总体的**金额**，不计算收益率；
  - 总资产盈亏 = `总资产(t1) − 总资产(t0) − 外部本金净流入`；
  - 类别盈亏 = `类别市值(t1) − 类别市值(t0) − 该类别净资金流入 − 该类别转账损耗`；
  - 「资金流入」指跨类别转账、外部本金入金/出金、调整；分红/利息/支出不作为资金流，保留在市值变化中；
  - 分红支付瞬间不产生盈亏（净值下跌与现金增加抵消）；如需「分红收入」统计，后续版本单独提供；
  - 支出（手续费等）已通过现金余额变化计入盈亏；转账损耗（转出价值与转入价值之差）单独计入盈亏，金额可为负；
  - 历史估值使用历史价格与历史汇率；资金流按事件发生日汇率折算；
  - 历史数据缺失时，使用事件快照（FR-TX-13）计算近似值，并标记「近似」。
- **FR-CALC-06 币种分布**：
  - 默认按标的币种分类：CNY、USD、HKD、实物黄金；CNH 在 v1 归入 CNY；
  - 现金标的按币种；
  - 黄金默认归入人民币；可由用户把实物黄金标的配置为「实物黄金」；
  - 支持每个标的配置「币种暴露」覆盖（自动/CNY/USD/HKD/实物黄金）。
- **FR-CALC-07 机构分布**：
  - 按机构汇总当前 CNY 市值；
  - 机构可配置图表显示别名（seed：人民银行 → 熊猫金币）。
- **FR-CALC-08 精度**：
  - 金额、数量、单价用十进制字符串/定点十进制计算；
  - 展示时按标的/币种精度四舍五入；
  - 禁止用 `Double` 累计金额。

### 6.10 首次启动与空状态

- **FR-ONBOARD-01**：首次启动直接使用固定目录 `Documents/folio-prism/`；不提供目录选择，不制作启动设置页。若目录不存在则创建；若缺少存储权限，跳转系统授权页。
- **FR-ONBOARD-02**：创建空数据文件，预置 7 大类、类别颜色与 invest-folio 当前的目标/上下限（可修改）。
- **FR-ONBOARD-03**：首页只显示空状态，不主动引导用户去设置或录入。

## 7. 非功能需求

- **NFR-01 独立性**：不依赖局域网服务器；所有计算、存储、行情抓取在手机上完成。
- **NFR-02 可靠性**：数据写入原子化；崩溃/断电后可恢复；保留备份。
- **NFR-03 性能**：按 1 万条事件的预期规模设计；启动、估值、图表切换无明显卡顿；当前行情并发获取；历史数据按需加载并缓存。
- **NFR-04 隐私**：数据不上传任何服务器；行情请求只包含标的代码；日志不含金额、数量、汇率。
- **NFR-05 兼容性**：minSdk 26；在 Redmi 14C 与 Xiaomi 17 Ultra 上运行；适配 HyperOS 的存储/网络限制。
- **NFR-06 可维护性**：计算核心为纯 Kotlin、可在 JVM 上单元测试；行情适配器可独立测试。
- **NFR-07 可读性**：数据文件为格式化 JSON，用户可用文本编辑器查看和手工编辑。
- **NFR-08 可恢复性**：备份文件带时间戳；主文件损坏时可从备份恢复。

## 8. 验收标准（关键场景）

### AC-01 首次启动
- 给定全新安装且已授予存储权限，App 直接创建 `Documents/folio-prism/folio-prism.json` 与 `price-cache.json`，并显示空状态首页；不出现目录选择或启动设置页。
- 若未授予「所有文件访问」权限，App 跳转系统授权页；拒绝后显示调试页说明原因。

### AC-02 启动价格门禁
- 给定任一非零持仓的首选行情源失败，当 App 启动时，显示调试页而非首页。
- 调试页列出失败标的、首选源与错误；点击刷新后若恢复，进入首页。
- 价格缓存文件存在但行情失败时，仍然显示调试页，不得用缓存估值。
- 调试页可为目标标的设置手工价格并重试，成功后进入首页。

### AC-03 估值与显示
- 给定多机构、多币种、含黄金加价的持仓，首页总资产与逐项市值按 6.9 公式计算，精度符合设置。
- 同一标的在两个机构持有时，行情只请求一次，两个持仓分别估值。
- 人民币计价资产只显示人民币；美元计价资产显示美元价值与人民币等值；类别汇总给出美元资产小计而不是整类美元换算。

### AC-04 再平衡
- 给定 invest-folio 当前规则与调试持仓，7 类卡片的目标金额、区间、缺口、黄金阈值价与 `portfolio.html` 的计算结果一致（金价/汇率相同时）。
- 红利使用 totalValue 基数，其他类别使用 portfolioValue 基数；图表的视觉宽度使用 totalValue 分母。

### AC-05 事件推导
- 录入一笔买入转账后，现金减少、持仓数量增加、总资产按新价格重算。
- 录入一笔卖出转账后，持仓减少、现金增加。
- 转账的转出与转入价值不同时，自动生成一笔关联的损耗支出，金额 = 转出价值 − 转入价值，可为负。
- 录入手工分红后，现金增加、来源持仓数量不变；勾选「立即转出」时再生成一笔关联的外部出金。
- 录入支出事件（手续费/损耗）后，现金或盈亏按事件规则变化；负值支出使现金增加/盈亏增加。
- 编辑或删除事件导致负持仓/负现金时不被阻止、不弹提示；数据由用户自行负责。
- 再投资由用户手工录入买入转账，不通过分红事件完成。

### AC-06 类别盈亏
- 给定一段历史区间与调试交易/行情，类别盈亏 = 期末市值 − 期初市值 − 期间净资金流入 − 转账损耗，误差在 0.01 CNY 以内。
- 跨类别买入、卖出、分红、支出、外部入金/出金分别按 6.9 分类，不重复计算。
- 历史价格缺失时，该类别标记「数据不完整」或「近似」，不输出伪造数字。
- 历史价格缓存损坏时，仍可基于事件中保存的价格/汇率快照计算交易行为之间的盈亏，并标记「近似」。

### AC-07 总资产曲线
- 曲线按日展示，非交易日沿用最近收盘价；缺失交易日显示缺口。
- 切换时间范围后，曲线与对应区间一致；显示缓存更新时间。

### AC-08 数据与备份
- 数据文件写入过程中断后，重新启动能从临时文件/备份恢复到一致状态。
- `Documents/folio-prism/` 中的 JSON 可被系统文件管理器复制；README 路径与实际路径一致。
- 备份达到保留上限（默认 5 份）后，最旧备份被清理。
- App 关闭时手工修改的 JSON 能被加载；格式错误时进入调试页并指出错误。

### AC-09 调试页
- 点击「保存日志」后，`logs/` 下生成带时间戳的日志文件，文件管理器可见。
- 日志包含失败来源、标的代码/名称与错误，不含金额、数量、汇率。

### AC-10 图表页
- 累计投入/取出图表按时间范围正确累计外部本金流入/流出，不依赖历史行情。
- 费用统计汇总支出事件（含转账损耗），负值支出参与抵扣，可按月份/类别分组。
- 机构/币种分布与当前持仓一致；CNH 在 v1 归入 CNY。
