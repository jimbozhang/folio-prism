## 1. 背景

当前有两套割裂的工具：

1. **invest-folio**：单文件 `portfolio.html`（原生 HTML/CSS/JS，约 1500 行），浏览器打开即用。它维护当前持仓数量，实时抓取公开行情接口，计算 CNY 市值、7 大类配置占比、再平衡缺口、券商/币种分布。它没有后端、没有数据库、没有交易流水、没有成本与盈亏。
2. **随手记（www.sui.com）**：用于记录投资相关的资金流水，导出为 4 个归一化 CSV。流水只有金额，没有份额、单价、成本、交易 ID；每月末还有大批手工录入的「红利收益/成长收益/…」补丁，破坏了流水的天然性。

两者的痛点：

- 记账工具不能动态跟踪资产单价，只能手工补月度估值；
- 估值工具没有交易流水，无法回答「投资到底赚没赚」；
- 同一只基金在不同机构无法合并统计；
- 两套工具意味着日常生活里要多用一个工具。

## 2. 目标

构建一个**单机 Android App**，替代 invest-folio 和随手记（仅投资记账部分），在一个工具里完成：

- 投资事件（转账/买卖、分红、利息、出入金、费用等）的录入与流水管理；
- 基于实时行情的持仓估值、7 大类配置与再平衡提示；
- 类别级盈亏、总资产曲线、投入取出、调仓统计、分红统计等分析；
- 数据本地保存、可通过手机文件管理器手工备份。

## 4. 用户与运行环境

- 单一用户。
- 目标手机：Xiaomi 17 Ultra（日常使用）；Redmi 14C（开发/调试机）。
- App 本身完全在手机上运行：计算、存储与行情抓取不依赖任何外部服务器，也不需要局域网内的其他机器。
- 可选提供**局域网数据服务**：用户手动开启后，同一局域网内的电脑浏览器可查看概览/图表、筛选并编辑流水；服务不开启时不影响 App 其他功能（见 6.11）。
- 数据固定保存在手机 `Documents/folio-prism/`；备份通过手机系统文件管理器手工操作。
- 需要联网获取行情；无网络时按第 6.1 节处理。
- UI 语言：中文。
- App 显示名：**资产配置**；包名：`com.jimbozhang.folioprism`。

## 5. 已确认的产品决策（Decision Log）

| ID | 决策 |
|---|---|
| D-01 | 原生 Android App（Kotlin + Jetpack Compose），替代 invest-folio 与随手记的投资记账部分；不记录日常收支，不做负债。 |
| D-02 | 单机运行，数据固定在手机 `Documents/folio-prism/`；不做应用内导入/导出 UI；备份由用户在文件管理器中手工完成；README 写明数据路径。 |
| D-03 | 目标机 Xiaomi 17 Ultra，开发机 Redmi 14C；只编译 debug APK 自用。 |
| D-04 | 首页 = 总资产 + 7 大类卡片（含再平衡信息），不显示盈亏；盈亏、曲线、分布、投入取出、调仓统计、分红统计等放在独立图表页。 |
| D-05 | 7 个战略类别固定：红利、成长、美股、美债、中债、黄金、现金。类别是用户给标的分配的「角色」，不是资产类型；例如债券基金 000015 可被归为现金。现金类标的同样需要实时估值。另可选配置第 8 类「卫星」（`specialRule = "satellite"`，在新增/编辑标的时可直接选择，首次保存自动创建，也可在 JSON 中添加）：市值计入总资产，但不设目标/区间，不参与再平衡、调仓建议与调仓统计，七类的目标基数剔除卫星。 |
| D-06 | 账户与标的分离：账户 = 机构（银行/券商），标的独立维护；持仓 = 机构 × 标的；同一标的在多个机构共享同一条标的记录。 |
| D-07 | 现金标的化：现金是「现金」类别下的标的（CNY/USD/HKD/CNH/活钱宝/美元定期等）；数量即金额；也可包含有净值的现金类基金（如 000015）。 |
| D-08 | 事件统一：买入、卖出、基金转换、跨机构搬仓、换汇都归为「转账」；另设收益（分红/利息）、外部入金/出金、支出、期初、调整事件。 |
| D-09 | 分红全部为现金分红，不做红利再投资。若用户实际做了再投资，由用户手工录入一笔买入转账，不并入分红事件。分红事件记录：来源标的/机构、入账现金账户、金额、是否立即转出到外部消费账户。 |
| D-10 | 多币种：交易按原币存储；单项资产按原币显示；只有需要把多个币种金额加总时（总资产、类别汇总、占比等）才折算为 CNY，且**只使用当前汇率**。不保存、不查询历史汇率。 |
| D-11 | 当前行情只使用 `portfolio.html` 中每个标的类型对应的**首选数据源**，不使用备选数据源；首选源失败即视为行情获取失败。打开时刷新一次 + 下拉刷新；无后台/定时刷新。 |
| D-12 | 启动价格门禁：任一持仓的必需价格（含汇率）无法获取时，不进入主界面，进入调试页。价格缓存**不能**作为当前估值的备用数据源。 |
| D-13 | 调试页：打印失败项、首选数据源、错误原因与日志；允许刷新；允许把日志保存到存储；允许为失败标的临时设置手工价格并重试。 |
| D-14 | 历史数据：按需抓取历史价格/净值并缓存；**不抓取、不缓存历史汇率**；历史统计中的外币资产用当前汇率折算。缓存可随数据一起被用户备份；用户指定的历史区间必须可计算。 |
| D-15 | v1 图表：类别盈亏、总资产变化曲线、类别资产、投入取出、调仓统计、分红统计、机构分布、币种分布。盈亏口径为「市值变化扣除资金流」；资产曲线按日拆分「资金流」与「市场盈亏」（期初 + 出入金 + 市场盈亏 = 期末），并支持切换为剔除资金流的净值曲线；v1 不做逐笔成本/收益率。「收益构成」即类别盈亏，不另设图表。费用统计不再单设图表，费用/损耗在调仓统计中汇总。 |
| D-16 | 数据存储：单个 JSON 文件（带 schemaVersion），原子写入 + 带时间戳备份（默认保留 5 份）；历史价格缓存独立文件；纯文本、不加密。 |
| D-17 | 机构、标的、黄金加价、类别目标/区间在 App 内编辑；类别名称内置不可编辑，类别的颜色与顺序固定，只能在 JSON 中手工修改；同时允许用户在 App 关闭时直接手工编辑 JSON 文件来设置和记录流水。 |
| D-18 | 历史回填：用户计划录入手头 4 个 CSV 中的全部真实流水（每月手工估值行除外）；录入效率与导入方式在实现前另行讨论。开发阶段用调试 JSON 文件，不提供模拟数据开关。 |
| D-19 | 计算行为与 `portfolio.html` 相同（除本文件明确修改的显示/事件规则外）。保留红利/组合双口径、再平衡缺口公式、黄金阈值价、黄金机构加价、机构/币种分布。 |
| D-20 | 技术实现细节（精确盈亏公式、缓存文件结构、图表库等）由开发方决定，但必须满足本文档的可观察行为。 |
| D-21 | 不提供数据目录选择，也不专门制作启动设置页；直接使用 `Documents/folio-prism/`。若系统未授予「所有文件访问」权限，跳转系统授权页。 |
| D-22 | 每笔事件只保存原币数量/金额/价格/费用/损耗；**不保存汇率，也不保存折算后的 CNY 金额**。外币估值与汇总使用当前汇率。 |
| D-23 | 转账记录「转出数量」与「转入数量」两个量，各自使用转出/转入标的的原币单位（现金为金额，有净值标的为份额）。两者按价值默认相等，也允许不同；差额写入转账事件自带的「损耗」字段（原币，可为负值），不另生成支出事件。需要从独立现金账户支付手续费时，使用转账事件的手续费字段。 |
| D-24 | 设独立的「支出」事件：投资手续费、转账损耗等；支出金额可以为负值（表示返还/收益）。 |
| D-25 | 不阻止也不提示会导致负持仓/负现金的编辑或删除；数据的正确性由用户自行负责。 |
| D-26 | v1 将 CNH 视作 CNY（1:1），后续迭代再支持 CNH/CNY 汇率。 |
| D-27 | 每笔事件保存原币价格/数量（D-22）；历史价格缓存只用于更精确的逐日曲线与区间估值，不是当前价格来源。 |
| D-28 | 预期事件规模为 1 万条（当前 444 条只是起点），性能设计按此规模考虑。 |
| D-29 | 日志允许包含标的代码与名称，不记录金额、数量、汇率。 |
| D-30 | 美股/美债等类别中，人民币计价资产（如 513500）以人民币显示，不显示美元等值；美元计价资产（如 VOO）直接显示美元价值，**不显示人民币等值**。类别汇总仍以 CNY 为口径（使用当前汇率），另给出美元计价资产的原币小计（同样不附人民币等值）。 |
| D-31 | 局域网数据服务：设置页手动开启，以 Android 前台服务运行；同一局域网内的浏览器可访问概览、图表与流水，并可新增/编辑/删除事件、下载与替换数据文件。服务不做鉴权，只适合可信局域网；网页端修改写回同一数据文件，App 需重启后才能在手机上看到。 |
| D-32 | 交易录入提供自动建议：转账按价值自动建议转入数量；来源持仓旁提供「自动」按钮按类别目标占比建议转出数量；转入侧提供「按目标占比」建议，同时填好转出与转入数量（受转出持仓价值上限约束）。价格用当前行情/手工价预填：预填只写入空字段或仍保留上次建议值的字段，用户手填后不再覆盖；清空字段后重新允许填入；切换标的后直接改用新标的报价。建议不覆盖用户已输入的值，用户输入优先。 |
| D-33 | 首页类别范围条使用与 `portfolio.html` 一致的自适应窗口；黄金卡片展开时在范围条上显示下限/上限对应的阈值单克价：金价源为 XAU 时两行显示（美元/盎司 + 换算的元/克），为 AU9999 时显示元/克；标准（目标）价不显示；折叠时不显示阈值单价。 |

## 6. 功能需求

编号规则：`FR-<模块>-<序号>`。每条需求都应能转化为验收测试。

### 6.1 启动与价格门禁

- **FR-START-01**：App 启动后先加载本地数据文件；若文件不存在，直接在固定目录创建空数据文件并显示空状态首页，不进入应用内设置页。
- **FR-START-01A**：固定数据目录为 `Documents/folio-prism/`。若系统未授予「所有文件访问」权限，显示权限说明页并跳转系统授权页；授权后继续。
- **FR-START-02**：加载数据后，必须获取所有「必需价格」后才能进入主界面。必需价格包括：
  - 所有数量非零、`kind=quoted` 的标的的当前价格；
  - 所有非 CNY 现金/持仓所需的当前汇率（v1 为 USD/CNY、HKD/CNY；CNH 视作 CNY，不需要汇率）；
  - 黄金类持仓所需的金价；
  - 已配置手工价格的标的视为价格可得，不触发失败。
- **FR-START-03**：任一必需价格获取失败（网络错误、接口无数据、解析失败、超时等），**不得进入主界面**，显示调试页。
- **FR-START-04**：调试页必须显示：每个失败项的机构、标的代码/名称、标的类型、首选数据源、错误原因；以及最近的应用日志。提供「刷新」「保存日志」按钮；对有标的 ID 的失败项，提供「设置手工价格并重试」（汇率等无标的的失败项不提供）。
- **FR-START-05**：保存日志时写入数据目录下的 `logs/`，文件名带时间戳；日志可包含标的代码与名称，不得包含金额、数量、汇率。
- **FR-START-06**：刷新成功后进入主界面；刷新仍失败则留在调试页。
- **FR-START-07**：价格缓存只用于历史统计，不参与启动估值，不得作为「当前价格」的备用源。
- **FR-START-08**：数据文件损坏/无法解析时，显示全屏「加载失败」页并展示错误信息，可重试；不得静默重置数据（主文件不存在时才创建空数据）。
- **FR-START-09**：当前价格不写入历史价格缓存；历史缓存只由历史行情抓取写入。

### 6.2 首页

- **FR-HOME-01**：显示总资产（CNY，汇总口径）。
- **FR-HOME-02**：显示红利小计与占比、组合（非红利）小计与占比。占比规则见 6.9。
- **FR-HOME-03**：显示 7 张战略类别卡片，顺序按设置中的类别顺序；总资产为 0（无持仓）时各类别市值 0、占比按 0% 展示，范围条照常绘制。若配置了卫星类别，在七张卡片之后追加一张紧凑的卫星卡片（名称、当前金额、占总资产比例、可展开持仓），不显示目标/区间/范围条，视觉上弱于战略类别卡片；资产配置卡片在战略类别行之后追加一行卫星（名称、当前金额、占总资产比例；条形只画填充，无区间带与目标线，占比用中性色），点击滚动到卫星卡片。卡片包含：
  - 类别名称、当前市值（CNY 汇总）；
  - 当前占比（区间内绿色、区间外珊瑚红）、目标占比；
  - 目标金额与最小/最大区间；
  - 范围条：自适应窗口（规则带 + 当前值，两侧留白 15%），区间内淡绿、区间外淡珊瑚色；带最小/最大灰色刻度、目标深色刻度、当前位置圆点；
  - 范围条下方标注最低/标准/最高的百分比与动态金额；展开卡片时额外显示阈值名称，以及各阈值与当前值的差值（当前值 − 阈值金额）；
  - 黄金类别展开时额外显示下限/上限对应的阈值单克价（XAU 两行：USD/盎司 + 换算 CNY/克；AU9999 一行 CNY/克；折叠时不显示；不显示标准价）。
- **FR-HOME-04**：单项资产按原币显示：
  - 人民币计价资产（如 513500）显示人民币，不显示美元等值；
  - 美元计价资产（如 VOO）显示美元价值，不显示人民币等值；
  - 类别汇总仍以 CNY 为口径；若类别内存在美元计价资产，额外显示「美元资产小计（原币）」，不把整个类别折算成美元，也不提供人民币等值。
- **FR-HOME-05**：点击类别卡片可展开该类的持仓明细：代码/名称、机构、数量/份额、单价（原币）、市值（原币）；不显示人民币等值。再次点击折叠。现金与黄金标的的行序与其他标的相反：第一行机构名，第二行代码/名称 + 金额（现金）或 数量 × 单价（黄金）；其他标的第一行代码/名称，第二行机构 + 数量 × 单价。
- **FR-HOME-06**：首页不显示盈亏金额。
- **FR-HOME-07**：首页支持下拉刷新（图表页同样支持）；刷新失败按 FR-HOME-08 处理。
- **FR-HOME-08**：刷新失败时进入全屏调试页，直到刷新成功；不得用旧价格或缓存价格展示总资产。
- **FR-HOME-09**：首页不得出现 `portfolio.html` 中的调试面板。

### 6.3 交易与事件

- **FR-TX-01**：支持以下事件类型：
  1. **转账**：任意两个持仓（机构 × 标的）之间移动价值。买入、卖出、基金转换、跨机构搬仓、现金换汇在账本上都统一为转账；UI 可提供「买入/卖出」等快捷预设，但生成的仍是转账事件；
  2. **收益**：现金分红/利息，入账到现金标的；支持立即转出到外部消费账户；
  3. **外部入金**：外部 → 现金标的，属于本金投入；
  4. **外部出金**：现金标的 → 外部，属于本金取出/消费；
  5. **支出**：投资手续费、转账损耗等；金额可以为负值（返还/收益）；
  6. **期初**：期初现金余额 / 期初持仓数量；
  7. **调整**：对某持仓做数量或金额调整（平账），需填写原因。
- **FR-TX-02**：转账必须记录两个量：
  - **转出数量**（`fromQuantity`）：转出标的的原币单位数量；现金标的为金额，有净值标的为份额；
  - **转入数量**（`toQuantity`）：转入标的的原币单位数量；规则同上；
  - 两者按价值默认相等，也允许不同；涉及有净值标的时记录相应原币单价；**不记录汇率，也不记录折算后的 CNY 金额**；
  - 当转出与转入价值不相等时，差额写入转账事件自带的「损耗」字段（`lossAmount`，原币，可为负值），不生成关联支出事件。
- **FR-TX-03**：投资手续费/损耗优先记录在转账事件中：差额记 `lossAmount`（同币种自动计算；跨币种在两端均可精确折算为人民币时自动计算，例如人民币现金 + 按人民币输入的港币单价，否则手动输入）；从独立现金账户支付的手续费记 `feePosition`/`feeAmount`/`feeCurrency`。也允许单独录入「支出」事件。
- **FR-TX-04**：收益事件字段：来源标的/机构（利息可为空）、入账现金账户、金额、币种、是否立即转出到外部（转出后自动生成一笔关联的外部出金）。**分红全部为现金分红**，不支持在分红事件里做再投资；再投资由用户手工录入一笔买入转账。
- **FR-TX-05**：所有金额、数量、单价使用十进制精确表示，禁止二进制浮点直接累加。
- **FR-TX-06**：事件列表按时间倒序、按日分组展示；支持按事件类型（全部/转账/收益/外部/支出/期初/调整）、机构、标的筛选，多个条件同时生效；机构与标的组合须命中同一持仓（转账两端不交叉匹配）。
- **FR-TX-07**：事件可编辑、可删除；**不阻止也不提示**会导致负持仓/负现金的编辑或删除；数据的正确性由用户自行负责。列表点击先打开交易详情，再从详情进入编辑；编辑已有事件时不允许更改事件类型。
- **FR-TX-08**：交易录入可使用当前行情/汇率做辅助：预填单价、跨币种折合显示、按价值建议转入数量；外币标的的单价可切换「原币 / CNY」输入，CNY 按当前汇率换算回原币后存储并显示折合原币价格；**汇率与折算金额只用于界面提示，不写入事件**（事件仍只存原币价格）。
- **FR-TX-09**：持仓数量、现金余额由事件推导；UI 不提供直接改持仓的入口（用户仍可在 App 关闭时手工编辑 JSON）。
- **FR-TX-10**：转账录入提供自动建议：按转出价值自动建议转入数量；来源持仓旁提供「自动」按钮，按类别目标占比建议转出数量；转入侧提供「按目标占比」建议，点击后按转入类别的目标占比同时填好转出与转入数量；所需价值超过转出持仓时按持仓上限填写并标注。任一端为卫星类别时不提供按目标占比的再平衡建议；建议不覆盖用户已输入的值。
- **FR-TX-11**：事件保存后立即参与估值与图表计算。
- **FR-TX-12**：删除机构或标的时，若存在引用它的事件，必须阻止；应先处理相关事件（结构性引用保护，与 D-25 的数值正确性无关）。
- **FR-TX-13**：每笔事件只保存原币数量/金额/价格/损耗/费用；不保存汇率，也不保存折算后的 CNY 金额。
- **FR-TX-14**：手工修改 JSON 必须在 App 关闭时进行；App 运行期间的修改可能被覆盖。
- **FR-TX-15**：每种机构 × 标的组合只允许一笔期初事件；录入第二笔期初时必须拒绝，并提示已有期初事件的日期。
- **FR-TX-16**：交易详情页展示该笔事件的完整字段（原币数量/价格/金额、机构与标的、备注等），提供「编辑」入口；删除在编辑页顶栏确认后进行。

### 6.4 图表页

图表类型共 7 种：总资产（含类别切换）、类别盈亏、投入取出、调仓统计、分红统计、机构分布、币种分布。默认打开「类别盈亏」；类别盈亏默认区间为「月初至今」，其余带区间的图表默认「年初至今」。区间栏左右箭头按整月平移；总资产、类别盈亏、投入取出、调仓统计、分红统计带区间栏，机构分布、币种分布不带。

- **FR-CHART-01**：总资产变化曲线：CNY 口径；按日数据点；时间范围可选（月初至今、近 1 月、近 3 月、年初至今、近 1 年、全部，或自定义起止日期）；非交易日沿用最近收盘价（最多回溯 30 天），仍缺数据时用已知价格点线性插值并在日志提示；无法估值的日期显示为缺口，不填 0；区间终点为今天时使用当前行情价格。区间摘要按「期初 + 出入金 + 市场盈亏 = 期末」拆分；可切换「含资金流 / 剔除资金流」曲线（剔除后只反映价格、分红与费用），并可叠加出入金标记（默认隐藏）。下拉刷新会重新获取当前行情并重建历史结果。
- **FR-CHART-02**：类别盈亏：展示各已配置类别（含卫星）的区间盈亏（CNY）；以列表 + 柱状图呈现；计算口径见 6.9；任一端点缺失的类别标记「数据不完整（缺少历史价格）」。点击某一类别时，展开一个下拉卡片，里面显示该类别各标的资产在相同时间区间内的盈亏金额和百分比；卡片合理设计字体大小与布局（浅灰圆角卡片、按盈亏降序、期初为 0 时不显示百分比）；现金类标的的盈亏为 0 时不在卡片中显示；展开为纯视图状态、不重新请求行情。
- **FR-CHART-03**：投入取出：按月展示外部资金投入、取出与净投入；数据来自外部入金/出金事件（不区分本金/消费），不依赖历史行情，始终可计算。
- **FR-CHART-04**：调仓统计：统计区间内不同标的之间的转账；按月按方向（现金→资产、资产→现金、资产→资产）展示笔数与金额，另展示平均间隔天数、近 30 天笔数、类别净流向、热门前几对、转账费用/损耗合计与对账脚注。点击类别净流向行或热门调仓对行时，展开一个下拉卡片，列出该切片对应的转账流水（每条三行：转出标的、转入标的、日期与金额，有损耗时附带损耗金额）；同一块内同时只展开一行，切换区间自动收起，展开为纯视图状态、不重新请求行情。同一标的换机构、现金换汇、现金类别内部转换单独计数，不计入调仓频次与金额；转出或转入类别为卫星的转账不计入任何调仓统计；金额按当前汇率折算，无法定价的一端留空但笔数照计。费用统计不再单设图表。
- **FR-CHART-05**：机构分布：按机构汇总当前 CNY 市值，显示金额与占比；金额为 0 的机构不显示；支持机构显示别名（如「人民银行」显示为「熊猫金币」，可配置）。
- **FR-CHART-06**：币种分布：按当前 CNY 市值展示 CNY/USD/HKD/实物黄金等；金额为 0 的币种不显示；CNH 在 v1 视作 CNY；分类规则见 6.9。
- **FR-CHART-07**：「收益构成」即类别盈亏（FR-CHART-02），不另设图表。
- **FR-CHART-08**：历史行情获取中显示加载状态（需要联网时带「正在获取历史行情…」文案）；失败时显示错误与重试按钮；连续失败按指数退避重试（24 小时起，上限 30 天），避免频繁请求数据源。
- **FR-CHART-09**：原「类别资产」页已并入「总资产」页：页头下方提供「类别」下拉菜单，选项为「总资产 + 各个类别（含卫星）」；选择某类别时只统计该类别，曲线、区间盈亏、当前金额与持仓明细均只针对该类别；复用同一份历史结果，切换类别不重新抓取行情。总资产范围显示全部类别的「当前类别金额」表，类别范围只显示该类别。
- **FR-CHART-10**：历史价格缓存可被用户通过文件管理器备份；App 不显示缓存文件路径与最近更新时间。
- **FR-CHART-11**：分红统计：统计任意区间（含起止日）内的现金分红，不含利息；金额按当前汇率折算 CNY。展示区间分红合计、分红笔数、月均分红、单笔最大、最近一笔；来源标的分布、月度分红、去向分布（立即转出 / 留存现金），自上而下按此顺序排列。点击任一分布块的行（来源标的、月度分红、去向分布）时，展开一个下拉卡片，列出该切片对应的分红流水（每条三行：来源标的、入账账户、日期与金额，立即转出的标注「立即转出」）；同一块内同时只展开一行，切换区间自动收起，展开为纯视图状态、不重新请求行情。缺汇率的分红不计入并提示「部分分红因缺少汇率未计入」。

### 6.5 设置

- **FR-SET-01**：机构管理：新增/编辑/删除机构；字段至少包含名称、类型（银行/券商/其他）、图表显示别名、备注。
- **FR-SET-02**：标的管理：新增/编辑/删除标的；字段至少包含：
  - 名称、代码、类别（7 个战略类别或「卫星」；未配置时选择卫星会自动创建该类别）；
  - 币种（CNY/USD/HKD/CNH）、单位（份/股/克/元/张等）；
  - 标的类型：`现金`（数量即金额）或 `有净值`（数量 × 单价）；
  - 行情方式：自动 / 手工价格 / 无行情；
  - 手工价格（行情方式为手工时输入）；
  - 价格与数量的小数精度、币种暴露、备注。
  - 新增标的时，代码行提供「获取名称」按钮：输入代码后点击，从对应行情源获取并预填名称（尽力而为：按代码路由到对应行情源；现金/手工价格标的不提供，查不到的代码不填）；仅当名称为空时填入，用户手填的名称不被覆盖；名称不为空时点击则提示先清空名称再获取。
- **FR-SET-03**：类别与再平衡规则：编辑 7 个战略类别的目标比例、最低、最高；八个类别的名称内置、不可编辑（JSON 中的 `name` 在加载时被规范化）；不允许新增/删除类别；卫星类别可在新增/编辑标的时直接选择，首次保存自动创建，管理页中为只读行；当前 UI 不提供修改颜色与顺序的入口（可在 JSON 中手工修改）。
- **FR-SET-04**：黄金：按机构配置人民币/克加价（允许负数）；选择默认金价源（XAU 或 AU9999）。
- **FR-SET-05**：数据：显示固定数据目录 `Documents/folio-prism/`、机构/标的/事件数量、备份保留份数（默认 5，仅展示；可手工编辑 JSON 的 `settings.backup.retainCount`）。不显示数据文件路径、价格缓存路径、最近备份时间或备份列表；备份通过文件管理器完成，App 不做导入/导出 UI。
- **FR-SET-06**：设置页不提供日志/调试入口；调试页只在行情获取失败时自动进入。
- **FR-SET-07**：不提供独立的「关于」页；App 版本显示在系统应用信息中。
- **FR-SET-08**：所有设置修改立即生效并原子写入数据文件。
- **FR-SET-09**：设置页按实际功能分区：数据、局域网数据服务、管理（机构 / 标的 / 类别与再平衡 / 黄金价格修正）。
- **FR-SET-10**：局域网数据服务：设置页提供开关；开启后以前台服务运行并显示可复制的 `http://<手机IP>:<端口>` 地址（端口从 8420 起尝试到 8430）；停止可通过开关或通知栏动作；服务不做鉴权，运行期间提示不要同时在手机端编辑数据，网页端修改需重启 App 后才能在手机上显示。

### 6.6 数据存储与备份

- **FR-DATA-01**：主数据保存为单个 JSON 文件，包含 `schemaVersion`、设置、机构、标的、事件。
- **FR-DATA-02**：写入必须采用「临时文件 + 校验 + 原子替换」策略，避免断电或崩溃导致文件损坏。
- **FR-DATA-03**：每次写入前保留带时间戳的备份，默认保留最近 5 份；保留份数当前只能通过手工编辑 JSON 的 `settings.backup.retainCount` 调整。
- **FR-DATA-04**：历史价格缓存保存为独立 JSON 文件，与主数据同目录，可被文件管理器备份。
- **FR-DATA-05**：数据文件与缓存文件固定放在 `Documents/folio-prism/`，不提供目录选择；README 写明路径。若系统未授予「所有文件访问」权限，跳转系统授权页。
- **FR-DATA-06**：App 不提供导入/导出 UI；用户通过文件管理器复制文件完成备份，或在 App 关闭时手工编辑 JSON。
- **FR-DATA-07**：JSON 使用 UTF-8、缩进可读；金额/数量/单价以十进制字符串存储。
- **FR-DATA-08**：主数据携带 `schemaVersion`（当前为 1）。当前版本尚未实现自动迁移链；不兼容的格式变更需用户借助备份手工处理。
- **FR-DATA-09**：主数据文件缺失时直接创建空数据（预置 7 类规则），不检查备份、不自动恢复；备份恢复由用户用文件管理器手工复制完成。
- **FR-DATA-10**：手工编辑的 JSON 在启动时严格校验结构（未知字段视为不合法）；不合法时显示全屏「加载失败」页与错误信息，可重试，不静默修复。

### 6.7 行情与刷新

- **FR-QUOTE-01**：当前行情只使用 `portfolio.html` 中每个标的类型对应的**首选数据源**；不使用备选数据源；首选源失败即视为行情获取失败。
- **FR-QUOTE-02**：标的行情路由至少支持：
  - 场外基金（6 位数字、非中债且不以 1/5 开头，净值，东财批量接口）；
  - 场内 ETF/债券（6 位数字且为中债类别或以 1/5 开头，现价，腾讯 kline）；
  - 美股/美股 ETF（2–5 位大写字母，USD，腾讯美股）；
  - 港股（5 位数字，HKD，腾讯港股，代码不足 5 位左侧补零）；
  - 黄金（AU9999 或 XAU，按设置的金价源）；
  - 现金（CNY/CNH 不需要行情；USD/HKD 需要汇率；汇率来源 `open.er-api.com`，只支持 USD/HKD）；
  - 手工价格。
- **FR-QUOTE-03**：刷新策略：打开 App 时刷新一次 + 首页/图表页用户下拉刷新；交易页与设置页不刷新；不做后台/定时刷新。请求超时固定为连接/读取 8s、整体 12s，同源最多重试 1 次。
- **FR-QUOTE-04**：同一标的被多个机构持有时只取一次价格。
- **FR-QUOTE-05**：数量为 0 的标的不要求行情。
- **FR-QUOTE-06**：行情失败时记录首选数据源、请求参数概要、错误原因，供调试页展示。
- **FR-QUOTE-07**：所有必需价格获取成功后才能展示总资产；不得用旧价格、缓存价格或 0 代替。

### 6.8 历史行情与缓存

- **FR-HIST-01**：历史价格用于：总资产曲线、类别盈亏、历史持仓估值。
- **FR-HIST-02**：查询某区间时，App 按标的抓取覆盖该区间的历史数据并写入缓存（每次抓取从区间起点前约 10 天开始）；缓存满足覆盖判定（起点前 30 天内有数据，且末端已到区间结束前的最近工作日；周末回退后最多再放宽 3 天以覆盖短假期）时直接使用，否则重新抓取。不得用过期的收盘价充当区间起点：那会把区间之外的涨跌计入区间盈亏。长假等数据源确无新数据的情形由抓取退避记录兜底（FR-HIST-04）。
- **FR-HIST-03**：历史数据源（每类只用一个首选源）：基金用东财 `pingzhongdata`；场内 ETF/债券与港股用腾讯 kline（港股为不复权 `day` 数组）；美股用新浪财经日线；黄金用新浪上海金期货 AU0 连续合约作为 AU9999 的近似，并在日志注明。**不抓取、不缓存历史汇率**。
- **FR-HIST-04**：数据源失效或历史数据缺失时：
  - 不得伪造数据；
  - 无法估值的日期曲线断开；
  - 盈亏标记「数据不完整」；
  - 提供重试；
  - 失败按指数退避（首次失败记录时间，重复失败从 24 小时起翻倍，上限 30 天）持久化到缓存，避免频繁请求数据源；
  - 当前版本不提供手工补录价格的入口。
- **FR-HIST-05**：缓存文件与主数据文件一起可被用户备份。
- **FR-HIST-06**：历史抓取成功时把数据合并写入缓存；抓取失败时记录最后失败时间与下次可重试时间。当前价格刷新不写入历史缓存。
- **FR-HIST-07**：非交易日（周末/节假日）沿用最近一个交易日的收盘价（最多回溯 30 天）；仍缺数据时用已知价格点线性插值并在日志提示；无法估值的日期标记不完整。
- **FR-HIST-08**：即使历史数据源缺失或缓存损坏，也能基于缓存中的已知价格点/事件价格插值计算交易行为之间的估值；结果只标记「数据不完整」并在日志说明，不单独输出「近似」标记。

### 6.9 计算规则（产品可观察行为）

计算行为以 `portfolio.html` 为准（除本文件明确修改的显示/事件规则外）。以下为实现摘要，开发者负责逐条对齐。

- **FR-CALC-01 估值**：
  - `kind=cash`：`市值CNY = 数量 × 汇率(币种→CNY)`；CNY 汇率为 1；CNH 在 v1 视作 CNY。
  - `kind=quoted`：`市值CNY = 数量 × 单价 × 汇率(标的币种→CNY)`。
  - 黄金：`单价CNY/克 = 金价(CNY/克) + 机构加价`；若金价源为 XAU，则 `金价CNY/克 = XAU美元/盎司 ÷ 31.1035 × USD/CNY`。
  - 总资产 = 所有持仓市值CNY之和。
  - 单项资产展示使用原币；CNY 仅用于需要加总的汇总口径。
- **FR-CALC-02 双口径**：
  - `totalValue` = 全部资产之和（含卫星类市值）；
  - `satelliteValue` = 所有 `specialRule = "satellite"` 类别市值之和；
  - `strategyValue` = `totalValue` − `satelliteValue`（策略资产）；
  - `portfolioValue` = `strategyValue` − 红利类市值；
  - 总资产拆分展示：红利占比 = 红利市值 / `totalValue`，组合占比 = `portfolioValue` / `totalValue`，卫星占比 = `satelliteValue` / `totalValue`，三者合计 100%；
  - 战略类别卡片占比：红利 = 红利市值 / `strategyValue`，非红利类别 = 类别市值 / `portfolioValue`；
  - 红利的目标/上下限金额用 `strategyValue` 作为基数计算；
  - 非红利类别的目标/上下限金额用 `portfolioValue` 作为基数计算；
  - 卫星类别不设置目标/上下限/差值，其展示占比为卫星市值 / `totalValue`；
  - 首页分配总览包含 7 个战略类别行；配置卫星类别时其后追加卫星行（占总资产比例，条形只画填充，无区间带/目标线），缩放仍只按战略类别定标；全图共用一条缩放：`scale = max(10%, 战略类别的 visualShare 与 visualTarget 最大值) × 1.15`，上限 100%；min/max 刻度不参与定标；条形按「值 ÷ scale」映射。
- **FR-CALC-03 再平衡金额**：
  - `dynAmount(p, base, catValue) = p × (base − catValue) / (1 − p)`；
  - 目标/下限/上限金额分别代入对应比例；
  - 差值 = 当前市值 − 对应阈值金额：为正是当前高于该阈值，为负是低于；
  - 首页范围条在最低/标准/最高刻度下分别展示百分比、动态金额和差值；展开卡片时额外展示阈值名称；
  - 范围条自适应窗口：`span = maxPct − min(minPct, share)`，`pad = max(0.15 × span, 0.5%)`，`barMin = max(0, min(minPct, share) − pad)`，`barMax = max(maxPct, share) + pad`；所有刻度与标记在该窗口内线性映射。
- **FR-CALC-04 黄金阈值价**：
  - `黄金总克数 = Σ 黄金类标的数量`；
  - `其他资产 = portfolioValue − 黄金类市值`；
  - `阈值单价CNY/克 = p × 其他资产 / ((1 − p) × 黄金总克数)`，p 为下限/上限比例（不含机构加价）；
  - 若当前金价源为 XAU，第一行显示 `USD/盎司 = 阈值单价CNY/克 × 31.1035 ÷ USD/CNY`，第二行同时显示 `CNY/克`（USD/CNY 汇率缺失时不显示美元行）；否则只显示 `CNY/克`；
  - 首页黄金卡片只展示下限和上限对应的单克价（仅卡片展开时显示），标准（目标）价不展示。
- **FR-CALC-05 盈亏（v1）**：
  - 只计算类别级/总体的**金额**，不计算收益率；
  - 类别盈亏 = `类别市值(t1) − 类别市值(t0) − 该类别净资金流入 − 该类别损耗`；界面上的区间总盈亏为各非空类别盈亏之和；
  - 「资金流入」：跨类别转账（仅当转出、转入类别不同）、有来源且跨类别的分红/利息、外部入金/出金、调整事件、区间内发生的期初事件（按事件价格/当日历史价折算）；
  - 支出事件不作为资金流：现金支出已通过现金余额变化计入盈亏；非现金损耗（position=null）按类别扣减；转账内嵌损耗 `lossAmount` 单独按类别扣减（**仅跨类别转账**；同类别转账的损耗已体现在该类别市值下降中，不再重复扣减）；从独立现金账户支付的手续费已在回放中扣减现金；
  - 同类别内部的转账/分红不记资金流，类别市值变化自然反映；
  - 分红/利息是来源资产的收益：有来源时，来源类别盈亏 = 该资产价格变化 + 分红金额；App 不引入除息/复权概念，价格按实际涨跌计算；是否立即转出不影响盈亏；如需单独统计「分红收入」，后续版本提供；
  - 历史估值使用历史价格；外币资产与资金流均按当前汇率折算；不抓取历史汇率；
  - 历史数据不足时用已知价格点线性插值，无法估值的端点标记「数据不完整」，不输出伪造数字。
- **FR-CALC-06 币种分布**：
  - 默认按标的币种分类：CNY、USD、HKD、实物黄金；CNH 在 v1 归入 CNY；
  - 现金标的按币种；
  - 黄金默认归入人民币；可由用户把实物黄金标的配置为「实物黄金」；
  - 支持每个标的配置「币种暴露」覆盖（自动/CNY/USD/HKD/实物黄金）。
- **FR-CALC-07 机构分布**：
  - 按机构汇总当前 CNY 市值；
  - 机构可配置图表显示别名（seed：人民银行 → 熊猫金币）。
- **FR-CALC-08 精度**：
  - 金额、数量、单价用十进制字符串/定点十进制计算；
  - 展示时按标的/币种精度四舍五入；
  - 禁止用 `Double` 累计金额。

### 6.10 首次启动与空状态

- **FR-ONBOARD-01**：首次启动直接使用固定目录 `Documents/folio-prism/`；不提供目录选择，不制作启动设置页。若目录不存在则创建；若缺少存储权限，跳转系统授权页。
- **FR-ONBOARD-02**：创建空数据文件（不创建 `price-cache.json`），预置 7 大类与类别颜色：红利目标 32%（区间 28.8%–35.2%）；其余 6 类目标各为去除红利后基数的 1/6（≈16.67%，区间 15%–18.33%）。目标与区间可修改。
- **FR-ONBOARD-03**：无持仓时首页仍显示 7 大类卡片（市值 0、占比 0%）及其目标区间，不显示「暂无数据」占位，也不主动引导用户去设置或录入。
- **FR-ONBOARD-04**：不提供模拟数据开关；开发/调试用数据放在 `debug/mock-portfolio.json`，由开发者手工复制到手机数据目录。

### 6.11 局域网数据服务（Web 工作台）

- **FR-WEB-01**：设置页提供「局域网数据服务」开关；开启后以后台前台服务（dataSync 类型）运行内置 HTTP 服务，端口从 8420 起尝试到 8430，显示可复制的 `http://<手机IP>:<端口>` 地址。
- **FR-WEB-02**：浏览器页面包含三个页签：概览、图表、流水。
  - 概览：总资产、红利/组合/卫星（有卫星时）、7 类卡片（目标区间条、阈值标注、持仓明细）；卫星只显示紧凑卡片，不进资产配置条；
  - 图表：总资产、类别资产、类别盈亏、投入取出、调仓统计、机构分布、币种分布、分红统计，支持区间预设；总资产/类别资产曲线含资金流与市场盈亏归因、剔除资金流曲线切换与出入金标记；
  - 流水：按类型/机构/标的/关键词筛选，新增、编辑、删除转账/收益/外部/支出/期初/调整事件，并可刷新行情；可追踪一个现金持仓，显示每笔影响它的交易前后余额。
- **FR-WEB-03**：网页端的事件写入走与 App 相同的仓储：全量重写主 JSON、写入前备份、更新 `meta.updatedAt`；网页端不能管理机构/标的/类别/设置。
- **FR-WEB-04**：服务不做鉴权、不加 HTTPS，只在可信局域网内使用；设置页需提示运行期间不要在手机端同时编辑数据，网页端修改需重启 App 后才能在手机上显示。
- **FR-WEB-05**：页面与图表库（Chart.js）随 APK 打包在 assets 中，不依赖外网；停止服务可通过设置页开关或通知栏动作。
- **FR-WEB-06**：顶栏提供数据文件「下载数据」与「上传数据」入口：下载以附件形式原样取回手机上的 `folio-prism.json`；上传仅接受名为 `folio-prism.json` 的文件，文件格式须通过数据文件严格校验（未知字段即拒绝），校验通过后替换手机上的 `folio-prism.json`（仍走仓储备份 + 原子写）。
- **FR-WEB-07**：顶栏提供「上传APK」入口：浏览器可上传本应用新版安装包，以原文件名保存到数据目录 `Documents/folio-prism/`，供手机从该目录直接安装升级；同名文件直接覆盖（D-34）。只接受以 `.apk` 结尾（忽略大小写）的文件；文件名不得为空、不得为 `.`/`..`、不得含路径分隔符；文件内容须非空且为有效 APK（ZIP 本地文件头校验）。保存到数据文件所在目录，复用现有「所有文件访问」权限，不新增权限。

## 7. 非功能需求

- **NFR-01 独立性**：不依赖局域网服务器；所有计算、存储、行情抓取在手机上完成。
- **NFR-02 可靠性**：数据写入原子化；崩溃/断电后可恢复；保留备份。
- **NFR-03 性能**：按 1 万条事件的预期规模设计；启动、估值、图表切换无明显卡顿；当前行情并发获取；历史数据按需加载并缓存。
- **NFR-04 隐私**：数据不上传互联网；行情请求只包含标的代码；日志不含金额、数量、汇率。局域网 Web 工作台由用户手动开启且无鉴权，只在可信局域网内使用。
- **NFR-05 兼容性**：minSdk 26；在 Redmi 14C 与 Xiaomi 17 Ultra 上运行；适配 HyperOS 的存储/网络限制。
- **NFR-06 可维护性**：计算核心为纯 Kotlin、可在 JVM 上单元测试；行情适配器可独立测试。
- **NFR-07 可读性**：数据文件为格式化 JSON，用户可用文本编辑器查看和手工编辑。
- **NFR-08 可恢复性**：备份文件带时间戳；主文件损坏时可从备份恢复。

## 8. 验收标准（关键场景）

### AC-01 首次启动
- 给定全新安装且已授予存储权限，App 直接创建 `Documents/folio-prism/folio-prism.json`（不创建 `price-cache.json`），并显示空状态首页；不出现目录选择或启动设置页。
- 若未授予「所有文件访问」权限，App 显示权限说明页并跳转系统授权页。

### AC-02 启动价格门禁
- 给定任一非零持仓的首选行情源失败，当 App 启动时，显示调试页而非首页。
- 调试页列出失败标的、首选源与错误；点击刷新后若恢复，进入首页。
- 价格缓存文件存在但行情失败时，仍然显示调试页，不得用缓存估值。
- 调试页可为目标标的设置手工价格并重试，成功后进入首页。

### AC-03 估值与显示
- 给定多机构、多币种、含黄金加价的持仓，首页总资产与逐项市值按 6.9 公式计算，精度符合设置。
- 同一标的在两个机构持有时，行情只请求一次，两个持仓分别估值。
- 人民币计价资产只显示人民币；美元计价资产只显示美元价值；类别汇总给出美元资产原币小计，不附人民币等值。

### AC-04 再平衡
- 给定 invest-folio 当前规则与调试持仓，7 类卡片的目标金额、区间、差值与 `portfolio.html` 的计算结果一致（金价/汇率相同时）。
- 红利使用 totalValue 基数，其他类别使用 portfolioValue 基数；总览图全图共用同一条缩放，视觉宽度使用 totalValue 分母。
- 黄金卡片展开时在范围条上显示下限/上限单克价：XAU 来源两行（USD/盎司 + 换算 CNY/克），AU9999 来源为 CNY/克；折叠时不显示；标准价不显示。

### AC-05 事件推导
- 录入一笔买入转账后，现金减少、持仓数量增加、总资产按新价格重算。
- 录入一笔卖出转账后，持仓减少、现金增加。
- 转账的转出与转入价值不同时，差额写入转账事件自带的损耗字段（原币，可为负），不生成关联支出事件。
- 录入手工分红后，现金增加、来源持仓数量不变；勾选「立即转出」时再生成一笔关联的外部出金。
- 录入支出事件（手续费/损耗）后，现金或盈亏按事件规则变化；负值支出使现金增加/盈亏增加。
- 编辑或删除事件导致负持仓/负现金时不被阻止、不弹提示；数据由用户自行负责。
- 再投资由用户手工录入买入转账，不通过分红事件完成。
- 点击转入侧「按目标占比」建议后，转出数量与转入数量同时填入，转账价值一致；若所需价值超过转出持仓价值，则按持仓上限填写并提示受上限约束。

### AC-06 类别盈亏
- 给定一段历史区间与调试交易/行情，类别盈亏 = 期末市值 − 期初市值 − 期间净资金流入 − 转账损耗，误差在 0.01 CNY 以内。
- 跨类别买入、卖出、分红、支出、外部入金/出金分别按 6.9 分类，不重复计算。
- 区间内发生的期初事件按资金流处理，不计入盈亏；入金/出金同样不计入盈亏。
- 分红计入来源类别的盈亏：价格按实际涨跌计算（不区分除息），来源类别盈亏 = 价格变化 + 分红；立即转出不影响结果；无来源的利息计入现金类别。
- 同类别转账的内嵌损耗只体现在该类别市值下降中，不再额外扣减（不重复计算）。
- 点击某类别展开的下拉卡片中，该类别各标的盈亏之和 = 该类别盈亏（跨类别支出按类别级归属口径，可能略有出入）；同一标的盈亏 = 期末市值 − 期初市值 − 标的资金流 − 归属损耗。无来源的收入（利息）不计为标的资金流，直接计入入账标的的盈亏。
- 历史价格缺失时，该类别标记「数据不完整（缺少历史价格）」，不输出伪造数字。
- 历史价格缓存损坏或缺失时，使用缓存中的已知价格点/事件价格线性插值并记录日志，不单独输出「近似」标记。

### AC-07 总资产曲线
- 曲线按日展示，非交易日沿用最近收盘价（最多回溯 30 天）；仍缺数据时用已知价格点插值并记录日志；无法估值的日期显示缺口。
- 切换时间范围后，曲线与对应区间一致；同一区间在切换图表类型时复用历史结果。
- 历史行情获取失败时显示错误与重试；连续失败按指数退避。

### AC-08 数据与备份
- 主数据写入采用「临时文件 + 校验 + 备份 + 替换」；写入前备份失败会中止保存。
- `Documents/folio-prism/` 中的 JSON 可被系统文件管理器复制；README 路径与实际路径一致。
- 备份达到保留上限（默认 5 份）后，最旧备份被清理。
- App 关闭时手工修改的 JSON 能被加载；格式错误时显示全屏「加载失败」页与错误信息。
- 主文件缺失时直接创建空数据，不自动从备份恢复。

### AC-09 调试页
- 点击「保存日志」后，`logs/` 下生成带时间戳的日志文件，文件管理器可见。
- 日志包含失败来源、标的代码/名称与错误，不含金额、数量、汇率。

### AC-10 图表页
- 投入取出图表按时间范围正确累计所有外部资金流入/流出，不依赖历史行情。
- 调仓统计只计入不同标的之间的转账（现金→资产/资产→现金/资产→资产），按方向分月展示笔数与金额，并给出平均间隔、近 30 天笔数、净流向与热门前几对；同一标的换机构、现金换汇、现金内转换单独计数；费用/损耗合计在脚注展示。
- 机构/币种分布与当前持仓一致；CNH 在 v1 归入 CNY。
- 默认打开类别盈亏（区间月初至今）；其余图表默认年初至今；区间箭头按整月平移。

### AC-11 局域网数据服务
- 设置页开启服务后，同一局域网内的电脑浏览器可打开概览、图表与流水页；关闭服务后页面不可访问。
- 在网页端新增/编辑/删除事件后，手机上的 `folio-prism.json` 被备份并原子更新；重启 App 后可见修改。
- 服务不做鉴权；页面与 Chart.js 均来自 APK 内置资源，不访问外网。

### AC-12 黄金阈值单克价
- 黄金卡片展开时：金价源为 XAU，范围条下限/上限下方分别显示两行（`$x/盎司` + 换算的 `¥x/克`）；切换为 AU9999 后显示 `¥x/克`；标准刻度不显示单价；卡片折叠时不显示阈值单价。
- 阈值单克价不含机构加价；换算公式见 FR-CALC-04。

### AC-13 分红统计
- 给定区间内包含分红、利息、区间外分红和不同入账账户的事件：分红统计只计入区间内分红（不含利息），合计、笔数、来源、去向、月度分组与事件一致。
- 标记「立即转出」或有外部关联出金的分红计入「立即转出」，其余计入「留存现金」；两者之和等于分红合计。
- 分红币种缺少汇率时，该笔不计入并显示不完整提示。
